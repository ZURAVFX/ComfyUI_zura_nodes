# Zura Studio: implementation checklist

Goal: preserve the approved character workflows while making the requested media,
generation and viewing controls dependable and easy to discover. Changes are local
until a release is explicitly requested and the relevant flows are verified.

- [x] Keep H3 OpenJutsu and Wan Animate 2 available for character plus background replacement; retain OpenJutsu's background-preserving route and existing approved workflows.
- [ ] Add LTX-only HDR and SDR processing and delivery following official 2.5 examples. Bounded SDR-to-HDR and HLG-to-HDR previews passed short engineering tests with HLG, EXR and audio. PQ video and ACEScg EXR input passed GPU engineering tests; independently computed PQ/HLG neutral swatches passed ingest and HLG output round-trip checks. Tagged Display-P3/PQ input has independently checked synthetic decoding and colour conversion; unsupported or ambiguous tags are rejected. EXR auto-detection checks every frame. A 121-frame experimental temporal test renders real PQ footage; a 17-frame 1080 × 1920 reference also delivered correctly tagged HLG. Two private SDR-to-HDR GPU tests, with and without a continuation anchor, each rendered a 10-frame synthetic fixture in two sections and delivered ten EXRs and a correctly tagged 10-bit HLG video. An anchored 48-frame real-clip test produced three sections, 48 EXRs and a 10-bit HLG video; source audio cross-correlation measured zero sample lag. Artist review of the joins and longer public workflows remain. HDR previews currently cap runs at 121 frames and often fewer at high resolution.
- [ ] Provide an in-app model setup flow showing missing files, dependencies, sizes and download progress, with explicit user initiation. The FLUX.2/3, OpenJutsu, Wan Animate 2 and partial LTX 2.5 packages are implemented; LTX Gemma, clean plate, outpaint, H3 first/last, H3 control, H3 Ref2VA DMD, two head-swap adapters and Wan relight packages are also listed. The newly added primary model and adapter files match installed files by SHA-256; users must review individual source and upstream terms. An installed H3 INT8 VAE uses a different same-named version from the pinned download, so Studio protects it and describes the mismatch without assuming it is broken. Direct setup appears in main video, first/last-frame, reference-video and Paintout workspaces; frame extension reports long-clip dependencies. HDR controls link directly to the selected adapter package and explain that core dependencies are separate; automatic detection of every HDR dependency, remaining workspace entry points, the exact reduced-rank TaoMate adapter and custom-node installation remain outstanding. Paintout's route mapping is tested; its loaded-source panel still needs a visual check in both hosts.
- [x] Make ProRes MOV previews playable while retaining the original media for processing; a real isolated-browser test played a synthetic ProRes/PCM MOV via an H.264 proxy while preserving the original file and SHA for processing.
- [ ] Find and fix opening-frame aspect changes and duration mismatches. The relight crop paths now match and the UI displays frame-aligned lengths. An exact one-frame shortfall at final mux is held to match the selected duration, with a real FFmpeg 23-to-24-frame test; larger shortfalls still fail visibly. LTX first/last audio now pads short references with silence to the selected video length. A one-second relight GPU test produced 24 frames at 24 fps with aligned original audio and no obvious framing jump. A four-second, two-window relight from 60 fps footage at a non-zero trim produced exactly 96 frames with zero measured soundtrack lag. Wan 2.1 relight validation no longer inherits the unrelated H3 five-second limit; a six-second graph passed the corrected source-selection validation and rendered 144 frames with zero measured audio lag. The custom-selection limit of 30 seconds is now reflected in the interface, while full-source selection remains separate. Real preparation and full-resolution reload tests cover 23.976, 25 and 29.97 fps. Representative real H3, LTX and Wan first/last and H3 reference outputs also matched their requested frame counts. Maximum-length and additional unusual-source-rate GPU cases remain to be checked.
- [x] Implement LTX video outpainting with a simple extension/crop control or existing black-area input, and verify real output with both approaches. The preferred black-guide approach is integrated as a five-second preview and passed a 12-frame real upload-to-render test; Already-black input now uses a reviewed masked fallback: a 12-frame GPU test filled the border and preserved dimensions and audio; a 150-frame guided and feathered masked test preserved audio and was approved by the user; the optional long route, timing, cancellation and production review are implemented and locally installed. The installed interface was visually checked with real footage; full-source selection and the numeric duration were verified. The short workflow also has an interactive trim and source-length option.
- [x] Offer optional compatible installed LoRAs in advanced controls, with model-family validation; do not silently apply incompatible weights. Image, H3, Wan and staged LTX routes have graph tests; starting-frame image generation now has separate LoRA controls and graph coverage. Optional controls now also cover HDR, frame extension, first/last, standard H3 reference video and paintout; Wan 2.2 uses separate phase selectors. Progressive FastH3 supports an experimental optional H3 adapter; real H3 and FastH3 tests confirmed adapter loading, but broad third-party LoRA quality is not guaranteed.
- [x] Support zoom, pan and reset in the main video, image, first/last-frame and reference-video previews; interaction tests cover playback and seeking. Desktop zoom and reset were checked; additional media types still need desktop visual confirmation.
- [x] Confirm FLUX.2 Klein 9B is the image generation default, and investigate face-identity and realistic-skin LoRAs with credible compatibility evidence. FLUX.2 Klein 9B produced a real 512 × 512 render in 12 seconds including model loading. A controlled FLUX.3 Consistency LoRA comparison showed additional skin detail but did not establish better identity; a matched Restore comparison added texture but also altered the face, so neither adapter is a verified identity improvement or enabled by default.
- [ ] Run focused automated tests and representative local GPU/UI tests; identify any quality-sensitive feature still requiring artist review and keep unverified modes clearly gated.

- [ ] Show clear, truthful progress across all modes. Event routing and stage labels were fixed for frame extension and HDR, and sampler labels clarified for image, first/last and reference video. HDR now retains an active job through transient connection errors and keeps controls disabled until cancellation is confirmed. The private long-HDR coordinator reports stage, completed sections and its active prompt, routes sampler events to the requesting Studio client, and waits for its own prompt to leave the queue before declaring cancellation. Simulated queue tests cover running and unrelated prompts, and an isolated three-section GPU test interrupted its second section, reached cancelled with an empty queue and published no partial output. Custom LTX LoRAs are validated before a long run and applied to each section in graph tests. Frame extension also waits for its active prompt to leave the queue before reporting cancellation; an installed multi-window test confirmed this. Image, first/last and paintout recheck completion history when a job disappears between status requests, preventing the finished result from being missed. UI tests pass; live websocket progress was observed in isolated Comfy and full desktop flow remains to be checked.

Completion means each exposed control changes the actual rendered result, preserves
existing approved paths, and has truthful limits and actionable errors. Maintain
notes on unsupported model capabilities rather than claiming generic HDR, LoRA or
duration support without evidence.
