# Zura Studio UI and installation audit

3 November 2026. Code, mounted DOM and interaction/state audit. No AI generations, quality comparisons, large model downloads or changes to generation recipes.

## Outcome

These fixes ship in 1.3.46. Restart ComfyUI after updating, then refresh Studio to load the browser sign-in backend and frontend together. The previous installed files were backed up before local verification.

The approved charcoal, lime and Manrope design remains. This pass removes specific obstacles rather than replacing the layout or hiding more core controls.

| Priority | Finding | Change |

| Medium | Concurrent catalogue refresh callers could continue before loading had finished. | All callers await one shared request, preventing an empty or stale setup panel during overlapping refreshes. |
| Medium | HDR trim handles were buried in advanced settings. | The source timeline is visible in the composer. Precise timing and colour overrides remain together in a clearly named disclosure. Invalid ranges remain visible. |
| Medium | Dedicated workspaces inherited the main video recipe's readiness label, such as Wan Relight in frame extension. | That label is only displayed for the main video recipe. Dedicated workspaces retain their own inline setup/readiness controls. |
| Medium | Some shared download controls used an undefined text-colour variable. | They now use Studio's actual dark/light foreground token; the browser sign-in primary action uses explicit dark text on lime. |
| Medium | Floating menus opened with the keyboard could remain stacked. | Unrelated floating menus close when another opens. Shared workflow menus handle arrows, Home/End and Escape without intercepting text-field editing. |
| Medium | Replacing or closing an image/setup panel could leave a browser connection attempt active. | Cancel pending device requests and stop polling when panels are disposed/rebuilt. Guard late responses and requests cancelled before device setup returns. |

## Hugging Face connection

The flow uses the official [Hugging Face OAuth device flow](https://huggingface.co/docs/hub/oauth) and its published [discovery metadata](https://huggingface.co/.well-known/openid-configuration). Zura Studio has a public client identifier, not an embedded client secret. Requested permissions are `openid profile gated-repos`, not private-repository access.

1. Select the workflow/model. The installer shows missing files and total download size, reusing existing models and the chosen model folder.
2. If gated access is needed, choose Sign in with Hugging Face. Complete the browser sign-in and grant permission. HF may ask for the short device code shown in Studio.
3. Review and accept each publisher's terms using the same account. Returning to Studio retries the requested download.
4. Some publishers require manual approval. Studio cannot bypass that approval and shows the access requirement rather than pretending the model is installed.

Tokens remain on the ComfyUI server. Remember is optional; Windows uses DPAPI and other platforms use an owner-only file. Expired browser credentials request sign-in again. Existing HF CLI credentials, an advanced read-token fallback, and verified browser-file import remain supported. Missing node extensions are distinct from missing weights and may still require installing/enabling the extension and restarting ComfyUI.

Verified against real HF: public-client registration and device-start handshake succeeded. Account authorisation, real gated-file download and popup visual behaviour have NOT been completed with a user's account. Mocked tests cover approval, pending, slowdown, expiry, denial, cancellation, blocked popup and recovery. This is implementation evidence, not a claim that live account approval has passed.

## Validation and limits

- 95 frontend suites passed. The JS runner disables unmocked global fetch; generation submissions in state tests are fixtures only.
- 30 backend tests passed across credentials, model-folder/install logic, real local HTTP routes and tiny fixture imports. No model weights were downloaded.
- Package validation passed.
- The mounted control audit visited all workflow entries, including HDR, Inpaint and Ripple, without submitting a generation. No unnamed exposed controls were found by this structural scan.
- Eleven runtime files were installed locally and byte/hash checked after backing up their previous contents.
- Automated browser visual inspection was unavailable because of the Windows browser-policy limitation. Narrow-window layout, theme rendering and actual browser popup behaviour remain visual checks, not signed-off evidence.
- No claim is made that all possible UI bugs have been eliminated. Existing artist-approved generation recipes and quality are outside this audit.

## Reproducing the checks

Run the frontend suites in `tests/` and `tests/paintout_updated/` with the DOM dependency described in CONTRIBUTING.md. `test_studio_accessibility.mjs` checks mounted workflow controls without submitting a generation. The native Panorama controls test additionally needs `PANORAMA_ROOT` pointing to an installed Panorama node directory.

Backend coverage is in `test_model_access.py`, `test_model_install.py`, `test_model_install_routes.py`, `paintout_updated/test_browser_model_import.py` and `paintout_updated/test_model_download_routes.py`. These use temporary storage and small fixtures, not model downloads or AI generations.
